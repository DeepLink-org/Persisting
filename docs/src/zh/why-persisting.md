# 为什么是 Persisting

Agent 可能先产出有用的结果，之后才发现很难回答“发生了什么”。Persisting
就是用来补上这段缺口的。

## 要解决的问题

Agent 会修改文件、调用工具、读取数据，并在一次长流程中持续做决定。终端
输出不足以安全审查；没有持久记录的沙箱难以复盘；原始事件日志又很难稳定查询。

Persisting 专注于持久 Agent 历史：

- **pChronicle 保存轨迹。** 它把支持的 Source 规范化为可查询 Dataset，方便
  之后检查、比较和改进 Run。

## 产品承诺

每条工作流都应该容易回答三个问题：

1. 记录了哪些 Agent、模型与工具调用？
2. 实际发生了什么或改动了什么？
3. 哪些证据和历史支持这个答案？

答案始终关联到已记录的 Source 及其版本；记录缺失仍然是结论的限制。

## 什么时候适合使用

当轨迹需要在终端关闭后仍可浏览、查询和交换时，使用 pChronicle 保存与分析持久历史。

如果只是运行一次无需审查、也无需留存历史的脚本，Persisting 可能不是必要的基础设施。
